## Confirmed static failure paths

- State allocation at 3455 originally left `batch` at 867 uninitialized. Early explicit cleanup before batch assignment could inspect indeterminate pointers. An exception during logits reserve (3565), any of the five decoder reserves (3570–3575), or graph metadata allocation (560–566, reached through four schedulers) could leak a state not yet returned to its caller. Patch 0001 initializes cleanup-visible state and owns it immediately, removes the twelve now-redundant manual frees and releases only on success. The outer catch returns null after unwinding.
- Backend setup (1341–1371) originally stored native handles in a vector with no cleanup owner. Vector insertion failure or CPU initialization failure after earlier backend acquisition leaked handles. A shared adoption helper owns the incoming handle through insertion; an owned local vector holds adopted handles until successful transfer.
- KV initialization obtains a local context at 1004. Null buffer failure at 1014–1017 or a subsequent exception missed `ggml_free` at 1022. A native guard now owns that context immediately and frees it on all exits. Backend buffers already adopted into the state remain state-owned.
- Batch allocation (491–499) originally dereferenced unchecked malloc results and left row-table entries indeterminate until visited. Each size is checked before multiplication, every malloc failure throws before dereference, and all row pointers including the terminator are zeroed before row acquisition. A local aggregate owner cleans partial allocations. The caller checks the completed top-level pointers before any batch preparation.
- Model `get_ctx` acquisition at 1709 could leak on map insertion (1714) or context-vector adoption (1715). The fresh context is now guarded through both operations. The temporary tensor metadata context at 1750 is guarded through all model vector/tensor preparation, with null checked before use. Its former manual free at 1857 is removed.
- Model buffer allocation at 1864 originally continued on null and could leak a nonnull handle if vector insertion at 1866 threw. Null now fails the load; the same adoption helper owns nonnull buffers through insertion.
- The top-level no-state model context allocation at 3822 originally preceded the exception handler. The failure branch at 3846 used `delete`, omitting native contexts/buffers freed by `whisper_free` at 3984. A value-initialized context is now immediately owned with the complete normal deleter. Cleanup reads only the initialized model vectors and state pointer. Loader close is attempted once across allocation/load/close exceptions. The file wrapper owns the returned model through `path_model` assignment at 3768, including allocation failure there.

## Narrow production-path checks: feasibility only

No new hook, source patch, test target or runtime operation was added for the options below. They require a separately reviewed implementation and coordinated sequential execution.

1. A tiny invalid-magic in-memory loader can call the existing real `whisper_init_with_params_no_state` API and count its actual `close` callback. A C++ callback that throws on close can check the real once-only close/catch path without model weights or microphone input. This reaches context allocation and early model-load failure, not native tensor/buffer ownership or post-load path assignment. Backend registry/log initialization may still occur before the magic check; its cost and behavior must be assessed before execution.
2. A separate test translation unit could compile the exact patched `src/whisper.cpp` once, with its normal dependency configuration, making its private types/static batch functions visible to that test without adding a shipped API. It could call the real batch initializer/free with tiny valid and invalid dimensions and free an empty, value-initialized real state. Build configuration, duplicate-symbol avoidance and the intended no-backend-execution boundary need review. This would improve actual-type/basic cleanup coverage, but would not inject failures at the real malloc, backend or graph sites by itself.
3. Exhaustive named production failure sites need either a bounded valid model fixture plus controlled dependencies or a narrowly scoped compile-time dependency seam around those sites. Any proposed seam must retain the actual initializer/deleter control flow, use per-test counting fake acquisitions, and be absent from the shipped target; it must not add environment triggers, runtime function-pointer switches, global platform allocation interposition or public test ABI. It would require a new locked patch, independent review and proof that production build defaults are unchanged. None exists at this checkpoint. Global fail-next allocation alone cannot reliably identify a requested production site amid registry/log/backend allocations.

A future production-path run must identify the exact function/site reached and injected, expected acquisition/release counts, observed null/error result, absence of an escaping exception and recovery into a fresh instance. Mutating the corresponding production owner/guard/check should make that targeted test fail. Until that evidence exists, the passing result remains a generic-helper harness result with mirrored wiring, not a completed production failure matrix.

## Optional encoder environment

Pinned `src/CMakeLists.txt:193` compiles the ANEForge adapter. `src/whisper.cpp:3553–3560` reads `ANEFORGE_ENCODER`; `src/aneforge/whisper-aneforge.cpp:54–59` reads `ANEFORGE_DYLIB` and uses `dlopen` with `RTLD_NOW | RTLD_LOCAL`. The bridge rejects either variable being present, including an empty value, both before model creation and immediately before decoder-state initialization. The pure predicate fixture calls `ow_backend_environment_allowed` with supplied nullable strings. It does not read or set process environment variables, execute either production creation-site check, load a model or exercise dlopen. This guard addresses inherited optional encoder configuration; it is not a security boundary against arbitrary hostile code already executing inside the process or concurrent environment mutation by such code.
